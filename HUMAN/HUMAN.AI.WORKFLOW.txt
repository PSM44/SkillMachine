==========
01. EXECUTIVE INTENT
==========

SkillsMachine exists so that a Human can work with AI under explicit authority, without losing control of meaning, structure, or canonical state (estado canónico: the authorized project truth).

The AI-assisted workflow is the operating model (modelo operativo) that turns Human intent into planned work, isolated execution, evidence, and—only when authorized—canonical application (aplicación canónica).

It is not an informal chat substitute. It is not a framework. It is not a Skill and not a GRC (governance, risk, and compliance; gobierno, riesgo y cumplimiento).

This document explains intent and collaboration. Skills remain the Single Source of Truth (SSOT, fuente única de verdad) for reusable how-to. GRCLake remains the SSOT for mandatory controls and fail-closed Gates (condiciones obligatorias de avance).

==========
02. DESIRED OUTCOME
==========

A new Human operator or a newly initialized AI who reads this file, then the referenced Skills/GRCs, should be able to:

1. State who may speak to whom.
2. Distinguish a role from a Work Unit (unidad de trabajo).
3. Keep proposals (propuestas) out of canon until the Apply Path completes.
4. Choose sequential execution as the safe default for shared-state mutation.
5. Use graphs, loops, and alternative paths only when they are justified.
6. Return evidence that a Coordinator can accept and an Orchestrator can present to Human.

CURRENT_STATE_SUMMARY:
SkillsMachine currently has Human authority, sequential mutation, proposal isolation, and canonical-applier controls. Coordinator, typed Work Units, graph/loop/path lifecycles, heartbeat, timeout, and cancellation remain partial, candidate, or absent.

TARGET_STATE_SUMMARY:
The target workflow formalizes those missing capabilities while preserving Human authority, framework neutrality, and one authorized canonical applier.

Definition of Done (DoD, definición de terminado) for this conceptual artifact, after recorded Human review: the workflow is understood; Skills/GRCs remain owners of procedure and control; no framework is treated as mandatory.

06. END-TO-END OPERATING MODEL
==========

Global flow:

Human states intent.
Orchestrator turns intent into an objective package and, when needed, a decision package.
Coordinator produces a plan: Work Units, path eligibility, isolation proof, acceptance criteria.
Human authorizes through Orchestrator when the plan is material.
Executor validates and runs Work Units in authorized perimeters.
Work Units return isolated results.
Executor consolidates evidence.
Coordinator checks acceptance.
Orchestrator reports to Human.
If and only if Human authorized canonical application, Executor runs the Apply Phase under an exact allowlist.

==========
09. WORK UNIT MODEL
==========

A Work Unit is a bounded mechanism with identity, isolation boundary, timeout policy, retry policy, and acceptance reference.

Types:

DIRECT — deterministic execution without autonomous agent reasoning.
AGENT — an AI model with instructions and authorized tools performing a bounded task.
LOOP — bounded repetition with explicit stop conditions.
GRAPH — node-and-edge structure for dependencies, branching, joins, state, checkpoints, or Human-in-the-Loop (HITL, intervención humana dentro del flujo).
TOOL — a single authorized deterministic capability.

ROLE_IS_NOT_WORK_UNIT=YES
AGENT_IS_NOT_GRAPH=YES
LOOP_IS_NOT_GRAPH=YES
PATH_IS_NOT_LOOP=YES
GRAPH_NODE_IS_NOT_AUTHORITY_ROLE=YES
ADAPTER_IS_NOT_CANON=YES

Status: typed WU model = CANDIDATE/PLANNED as lake objects. Isolated proposal work = ACTIVE_EXISTING in Skill 02 and sequential GRC.

D3 purpose: choose the lightest safe controlling mechanism.


12. BOUNDED LOOPS
==========

A LOOP is a repetition object with LOOP_ID, stop predicate, and isolated outputs per iteration.

Proposed generalized LOOP object (CANDIDATE / CANONICAL_DIRECTION_PENDING_ALIGNMENT; not transversal active canon):

PROPOSED_DEFAULT_MAX_ITERATIONS_PER_LOOP=6

This three-failure rule is ACTIVE_EXISTING for mutating agent tasks through GRC.AI_CODE_AGENT_SEQUENTIAL_WORKFLOW.txt.
For a generalized named LOOP object in the lakes, the same ceiling is proposed, not yet a distinct lake contract.

Clarifications:
- Six is a proposed default ceiling, not mandatory consumption and not an active transversal HUMAN default.
- Iterations are not alternative paths. A loop repeats one bounded attempt; a path is a distinct hypothesis under one decision.
- Three equivalent consecutive failures cause hard stop under the sequential GRC for mutating agent tasks.
- No fourth equivalent attempt without Human authorization.
- Retries remain inside the same isolation boundary.
- Autonomous delegation is not a retry strategy.

A named LOOP object in lakes remains PARTIAL_EXISTING / CANDIDATE. HybridGraphExec tooling is not this methodology’s SSOT.

==========
13. GRAPH WORK
==========

A GRAPH is justified when the work needs material branching, independent fan-out, dependency ordering, computational joins, checkpoints (puntos de recuperación), interruption and resume, bounded iterative state, or durable HITL.

A GRAPH is not justified for simple deterministic tasks, single-file transforms, work that can safely run sequentially, cosmetic path diversity, parallelism only because it looks faster, or shared canonical mutation without isolation.

SPEED_ALONE_IS_INSUFFICIENT.

Parallelism may improve speed only after independence, isolation, resource availability, disjoint write boundaries, deterministic consolidation, and single canonical-applier protection have been proven. Sequential GRC already forbids parallelism merely for speed. ACTIVE_EXISTING.

DEVELOPMENT_EFFICIENCY_OWNER=AI
EFFICIENCY_REVIEW_CADENCE=EVERY_5_OPERATIONAL_PROMPTS
EFFICIENCY_REVIEW_OUTPUT=ONLY_IF_ACTIONABLE
EFFICIENCY_REVIEW_SCOPE=parallel_discovery;gate_batching;mutation_serialization;temp_consolidation;baton_readiness;commit_grouping;test_strategy;tooling_readiness;security_quality;technical_debt
EFFICIENCY_REVIEW_QUESTION=Are we working as fast, safely and intelligently as possible, or are we serializing work that could safely run in parallel?
The AI owns the responsibility to proactively seek, propose and improve development speed, efficiency, certainty and safety.
Pablo should not have to rediscover that the workflow can be faster, more parallel, or more evidence-efficient.
Massive read-only discovery, dependency mapping, graph fan-out, gate batching, and portfolio sprinting are the default for broad discovery when isolation is proven.
Shared-state mutation, HUMAN edits, deletes, builds, installs, staging, commit and push remain serialized and gated.
Safety controls exist to enable intelligent throughput, not to force one-task-at-a-time bureaucracy where safe parallel discovery is available.

==========
14. ALTERNATIVE PATHS
==========

A Path (camino de exploración) is a materially distinct hypothesis under one decision. It is not a loop iteration and not a mandatory set of six.

Policy:
- Use alternative paths only when divergent exploration materially improves a decision.
- When used, define at least two materially distinct paths.
- Default ceiling: six paths per decision, not per graph.
- Stop when additional paths are redundant, dominated, immaterial, unsafe, or unsupported.
- Every path declares hypothesis, distinctness, scope, risk, expected value, success criteria, and stop condition.
- Negative results include evidence and Root Cause Analysis (RCA, análisis de causa raíz) classification.
- Executor consolidates mechanically.
- Coordinator evaluates and recommends.
- Human decides material alternatives through Orchestrator.
- Executor may auto-select only when a deterministic selection rule was explicitly pre-authorized.

Status: CANDIDATE as a lake object. Do not invent six dummy paths.

28. GLOSSARY
==========

Apply Phase — authorized canonical mutation performed only by Executor after the Apply Path. Not a Work Unit type.
Canonical apply (aplicación canónica) — writing durable project truth after Human authorization; proposals are not canon.
Checkpoint (punto de recuperación) — restore point used before risky mutation; Skill 16 owns how-to; Git remains Human-gated unless delegated.
Coordinator (coordinador) — planner of Work Units and acceptance criteria; CANDIDATE as lake ROLE_ID; does not mutate canon.
Definition of Done (DoD, definición de terminado) — explicit done criteria. This file separates CURRENT_ENFORCEABLE_DOD from TARGET_WORKFLOW_DOD.
Executor (ejecutor) — supervisor of authorized Work Units and sole canonical applier when the Apply Path is authorized; does not speak directly to Orchestrator.
Gate (condición obligatoria de avance) — a condition that must pass before proceeding; risk-tier GRCs may add stricter Gates.
Graph (grafo de ejecución) — node-and-edge Work Unit for branching, joins, checkpoints, or durable HITL; not a role and not self-promoting canon.
Handoff (transferencia controlada) — authorized transfer of a package between roles along Command or Result Path.
Heartbeat — periodic progress signal for long unattended runs; CANDIDATE as a lake object; not currently enforced.
Human-in-the-Loop (HITL, intervención humana dentro del flujo) — a required Human decision or confirmation inserted into a run so material choices are not completed autonomously.
Loop (bucle acotado) — bounded repetition of one attempt with explicit stop conditions; iterations are not alternative paths.
Orchestrator (orquestador) — Human interface that frames packages and records authorization; does not run Work Units.
Path (camino de exploración) — a materially distinct hypothesis under one decision; default ceiling six per decision when paths are justified, not per graph.
Proof of Concept (PoC, prueba de concepto) — a bounded test of feasibility. It is not canon, not an adoption decision, and not a framework mandate.
Proposal (propuesta no canónica) — isolated non-canon output that remains a proposal until the Apply Path completes.
Rollback (reversión controlada) — restoring a known prior state after failed, blocked, or unauthorized mutation. Skill 16 owns how-to; Git commit remains Human-gated unless delegated.
Root Cause Analysis (RCA, análisis de causa raíz) — classifying why a path or iteration failed so the next attempt is not a cosmetic repeat of the same defect.
Sandbox (entorno aislado de ejecución) — an EXECUTION_SANDBOX_TEMP instance plus Skill 03 root rules. Folder isolation is not complete operating-system sandboxing.
Single Source of Truth (SSOT, fuente única de verdad) — the one owner for a class of rule: this file for workflow intent, Skills for reusable how-to, GRCLake for mandatory controls.
Timeout (tiempo máximo de ejecución) — the maximum allowed run time for a Work Unit. Expiry is a terminal stop, not a license to retry outside policy. CANDIDATE as a lake object.
Work Breakdown Structure (WBS, estructura de desglose del trabajo) — the ordered sectioning of this methodology from intent to references, and the Coordinator’s later decomposition of authorized work into Work Units.
Work Unit (unidad de trabajo) — a bounded mechanism: DIRECT, AGENT, LOOP, GRAPH, or TOOL. A role is not a Work Unit.

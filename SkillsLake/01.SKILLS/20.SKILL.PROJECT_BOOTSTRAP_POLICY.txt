==========
01.00_OBJETIVO
==========

Establecer un estándar mínimo obligatorio para que todo proyecto:

- tenga contexto para IA
- tenga continuidad
- tenga trazabilidad
- sea recuperable por terceros

El bootstrap crea solo el mínimo físico operable. El máximo lógico, perfiles y
triggers de crecimiento viven en SKILL.PROJECT_INFORMATION_ARCHITECTURE.txt.

==========
02.00_ARTEFACTOS_OBLIGATORIOS
==========

Todo proyecto DEBE crear:

1. HUMAN   (canon de producto; autoridad de identidad y límites)
2. BATON   (continuidad en frío; snapshot operativo para IA)
3. RADAR   (índice de estructura; Index obligatorio)

Sin estos 3 elementos:
→ el proyecto se considera NO-OPERABLE

WhoAmI:
- NO es artefacto obligatorio
- NO es requisito de operabilidad
- puede existir como referencia histórica u onboarding humano opcional
- su ausencia no convierte el proyecto en NO-OPERABLE

These three are bootstrap artifacts. Folder materialization beyond the files
needed to hold them follows SKILL.PROJECT_INFORMATION_ARCHITECTURE.txt
(three-artifact rule, hard exceptions, no empty logical-maximum tree).

==========
03.00_ORDEN_DE_CREACION
==========

Orden obligatorio (LIFECYCLE_ORDER / TEMPORAL_CREATION_ORDER del bootstrap):

01 → HUMAN
02 → BATON
03 → RADAR

Motivo:

- HUMAN define contexto base y canon de producto
- BATON sintetiza continuidad operativa para IA a partir de HUMAN
- RADAR mapea estructura

WhoAmI no entra en el orden obligatorio. Si un proyecto local lo conserva,
es opcional, claramente no operativo para bootstrap, y nunca un fallback
de HUMAN o BATON.

05.00_VALIDACION
==========

Antes de considerar proyecto válido:

- Existe HUMAN
- Existe BATON
- Existe RADAR_INDEX

Si falta alguno de esos tres:
→ FAIL

WhoAmI no forma parte de esta validación.
La ausencia de WhoAmI no produce FAIL.

Do not FAIL a new project for missing logical-maximum folders.

18.00_THREE_ARTIFACT_DIRECTORY_RULE
==========

Default:
Do not automatically materialize a functional directory without a reasonable
expectation of at least three related, durable, relevant direct artifacts.

What COUNTS as an artifact:
- current relevant durable files that belong to the role
- approved near-term artifacts (named, accepted, not hypothetical)

What does NOT count:
.gitkeep; cosmetic README; empty placeholders; shortcuts; temporary files;
caches; locks; copied previews; segments; hidden system files unless they are
the governed content; files created only to justify the directory.

Generated files COUNT only if they are durable role outputs (not caches).
Manifests COUNT when they are the role's real contract (not a stub).
Links/shortcuts do NOT count.
Placeholders do NOT count.

HARD exceptions (directory allowed with fewer than three):
authority boundary; security boundary; permissions boundary; operational interface;
external platform requirement; source/generated separation; independent lifecycle;
independent ownership; exact integration contract; mandatory bootstrap role.

DIRECTORY_CREATION_ALLOWED =
    HARD_BOUNDARY_REQUIRED
    OR RELEVANT_DURABLE_ARTIFACT_COUNT >= 3
    OR APPROVED_NEAR_TERM_ARTIFACT_COUNT >= 3
    OR PARENT_CONGESTION_REQUIRES_GROUPING

PARENT_CONGESTION_THRESHOLD=12 (default, configurable per project)
Verified as the live default from the approved architecture decision; not a universal law.
Projects MAY set another integer in BATON/project mapping; scanners MUST read the project value
when present, else 12.

Fewer than three files do not automatically create subfolders.
Never automatically collapse a directory because its count later falls below three.
Contraction/retirement uses an explicit promotion/retirement plan (19.00).

21.00_PHYSICAL_PATHS_AND_PORTABILITY
==========

Define paths by rules and variables, not by one machine's Windows path as universal law.

LOGICAL_ROOT     project identity root
PHYSICAL_ROOT    actual filesystem root (may differ: clone, worktree, sandbox)
REPO_RELATIVE    path from PHYSICAL_ROOT
EXTERNAL_PATH    outside the repo; declare, do not silently ingest
USER_PATH        human home/OneDrive/profile; not canon
TEMP_PATH        TEMP class locations
GENERATED_PATH   BUILD/RADAR/tool output
ACCESS_PATH      00_ACCESS entries (non-canonical)
HISTORICAL_PATH  retired/alias paths kept for resolution

Portability:
Windows is first-class here; it is not the only possible project OS.
Separators: store repo-relative paths with a documented convention; do not mix
unquoted raw "C:\..." as the generic standard for all projects.
Case: Windows case-insensitive default; do not rely on case as identity.
Forbidden characters: follow 06.SKILL.WBS / Windows rules for PHYSICAL_NAME.
Long paths: avoid deep cosmetic nesting; respect MAX_PATH risk.
OneDrive / network / reparse: detect; do not follow ACCESS reparse; record TARGET_ESTADO.
Hardlinks: identity by file-id; count once.

SkillsMachine repo physical root C:\01. GitHub\Skills is an instance, not a universal project root.

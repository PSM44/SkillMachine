==========
SKILL.COMPACT_UPLOAD_PACK_EXECUTION
==========

SKILL_ID: SKILL.COMPACT_UPLOAD_PACK_EXECUTION
SOURCE_MB: MB-SM-055J_CORE_HARDENING_COMPACT_UPLOAD_AND_ACCUMULATED_REGISTERS
MARKER: SM-055J-COMPACT-UPLOAD-PACK-EXECUTION
STATUS: ACTIVE_CANDIDATE_CORE
UPDATED_AT: 2026-07-05 01:04:17 -04:00

PURPOSE:
Define how long-running operational scripts must produce IA-readable upload evidence without flooding the user with raw logs.

METHOD:
1. Treat the declared Temp path as disposable scratch.
2. Clean Temp at the start of every runner.
3. If the currently executing .ps1 is stored inside Temp, preserve that .ps1 during cleanup.
4. Capture stdout/stderr from tools into memory or transient variables.
5. Consolidate relevant evidence into a small number of flat UPLOAD_*.txt files.
6. Persist AI_TAIL.<timestamp>.txt.
7. At the end, delete or avoid creating raw log files.
8. Leave only:
   - the executed .ps1 when stored in Temp;
   - AI_TAIL.<timestamp>.txt;
   - maximum 10 UPLOAD_*.txt files.

APPLIES_TO:
- Session continue runners.
- Session close runners.
- Commit/push runners.
- RADAR/readiness diagnostic runners.
- Any SkillsMachine package intended for IA upload.

OUTPUT STANDARD:
- UPLOAD files must be flat, readable, and self-contained.
- Tool stdout/stderr must be consolidated inside UPLOAD files.
- Do not ask the user to upload many logs.
- Prefer 4 to 6 upload files unless a stronger reason exists.

DONE WHEN:
- Temp output count stays within the upload cap.
- The user can upload the full evidence set without exceeding file limits.
- AI_TAIL includes TEMP_OUTPUT_POLICY=COMPACT_UPLOAD_PACK_ONLY.

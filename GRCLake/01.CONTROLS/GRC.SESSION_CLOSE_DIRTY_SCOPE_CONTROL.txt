CONTROL:
Session close runners must distinguish expected close-artifact dirty state from unexpected dirty state.

RULES:
1. Before SESSION_CLOSE artifact generation, the repo should be clean unless the runner explicitly declares a controlled exception.
2. After SESSION_CLOSE artifact generation, dirty files are allowed only inside the declared close output scope.
3. Git may report a new untracked directory rather than the exact new file. The runner must accept both:
   - the declared close directory;
   - files under the declared close directory.
4. Any dirty file outside the declared close scope is a blocker.
5. The runner must not declare a clean closure while readiness is WARN/FAIL.
6. The runner may declare review-required closure when the only dirty state is the expected close artifact.

AI_TAIL REQUIREMENTS:
- CLOSE_ARTIFACT_CREATED.
- CLOSE_FILE or CLOSE_DIR.
- UNEXPECTED_DIRTY_COUNT.
- READINESS_STATUS.
- COMMIT_PERFORMED.
- PUSH_PERFORMED.
- NEXT_ACTION.

7. CLOSE_IDENTITY_CONSISTENCY:
Session close artifacts must be identity-consistent: the project name, the
repository root, the BATON being refreshed, the close report, and the commit
(when one is authorized) must all reference the SAME project, root, branch,
and task identity. A close that mixes identities (e.g. a CloseReport-named
close operating on the SkillsMachine root) is invalid and must hard-stop
(see GRC.PROJECT_CONTEXT_IDENTITY).

8. EXACT_AUTHORIZED_DIRTY_PATHS:
The declared close scope is a list of EXACT authorized dirty paths (or one
declared close directory plus its files). Prefix or wildcard tolerance beyond
the declared close directory is not allowed.

9. PASS_WITH_REVIEW_CONDITIONS:
PASS_WITH_REVIEW closure is valid only when BOTH hold:
- an explicit blocker/review item is recorded; and
- there is NO pending mutation outside the declared close scope.

10. INDEPENDENT_COMMIT_AND_PUSH_STATUS:
Close reporting must state commit status and push status INDEPENDENTLY
(COMMIT_PERFORMED and PUSH_PERFORMED as separate fields). "Committed" never
implies "pushed"; neither may be inferred from the other.

11. UNKNOWN_DIRTY_SCOPE_HARD_STOP:
If any dirty path cannot be classified against the declared close scope, the
close hard-stops. Unknown dirty scope is never closed over, warned over, or
deferred silently (see GRC.UNKNOWN_WORKTREE_STATE_HARD_STOP).

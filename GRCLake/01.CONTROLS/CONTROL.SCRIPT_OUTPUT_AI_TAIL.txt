## 01. Purpose

This control defines the mandatory final output contract for executable scripts used in project workflows.

The goal is to preserve continuity when terminal output is long, truncated, visually wrapped, or partially pasted into an AI conversation.

This control applies across all projects, not only SkillsMachine.

## 02. Core Rule

Every future executable MB script should end with a compact AI_TAIL block.

The AI_TAIL block must be:

- located near the end of stdout;
- preceded by exactly six blank lines;
- delimited by visible AI_TAIL_START and AI_TAIL_END markers;
- concise;
- key-value based;
- stable enough for an AI assistant to parse from the last pasted lines;
- free of long prose, tables, stack dumps, or large inventories.

## 03. Exact Printed Delimiters

Scripts must print these exact delimiter lines:

********************** AI_TAIL_START **********************
********************** AI_TAIL_END ************************

## 04. Pasted Output Tolerance

The script must print the exact delimiters.

However, when reading user-pasted terminal output, an AI assistant may treat any line containing AI_TAIL_START as the beginning of the AI tail and any line containing AI_TAIL_END as the end of the AI tail.

This tolerance exists because terminal copy/paste may visually truncate the leading asterisks.

## 05. Required Final Layout

The final stdout layout should be:

1. START metadata.
2. Execution output.
3. Human summary.
4. Six blank lines.
5. AI_TAIL block.
6. END marker.

No material information should appear after AI_TAIL_END except the final END marker.

## 06. Mandatory Minimum Fields

Every AI_TAIL block must include:

AI_TAIL_SCHEMA=v1
MB_ID=<id>
FINAL_STATUS=<status>
BLOCKER=<none_or_reason>
BRANCH=<git_branch_or_NA>
HEAD=<git_head_or_NA>
DIRTY=<true_or_false_or_NA>
REPORT=<path_or_NONE>
NEXT_ACTION=<next_action>

## 07. Repository-Mutating Script Fields

Scripts that modify files, commit, or push must also include:

FILES_CHANGED=<count>
FILES=<pipe_separated_paths_or_NONE>
COMMIT=<hash_or_NONE>
PUSH=<OK|NO|FAILED>

## 08. Validation / Build Fields

Validation, build, or compile scripts should include when applicable:

VALIDATION=<PASS|FAIL|NA>
TESTS=<PASS|FAIL|NA>
BUILD_STATUS=<PASS|FAIL|NA>
BUILD_OUTPUT=<path_or_NONE>
BUILD_ERROR=<short_reason_or_NONE>
ARTIFACT=<path_or_NONE>

## 09. Beta / Launcher Fields

Launcher or beta-readiness scripts should include when applicable:

BETA_GATE=<PASS|FAIL|PARTIAL|NA>
USER_ENTRYPOINT=<path_or_command_or_NONE>
DEMO_READY=<true|false>

## 10. Field Rules

- Use one key per line.
- Use uppercase field names.
- Avoid prose inside values.
- Use NONE, NA, OK, FAILED, true, false consistently.
- Use pipe separators for path lists.
- Do not put tables inside AI_TAIL.
- Do not print JSON inside AI_TAIL unless explicitly required by a later schema.
- Keep AI_TAIL short enough to paste as the final terminal excerpt.

## 11. Example PASS

********************** AI_TAIL_START **********************
AI_TAIL_SCHEMA=v1
MB_ID=MB-EXAMPLE
FINAL_STATUS=PASS_COMMITTED_AND_PUSHED
BLOCKER=NONE
BRANCH=lab/example
HEAD=abc1234 commit_message
DIRTY=false
FILES_CHANGED=2
FILES=path/a.txt|path/b.txt
COMMIT=abc1234
PUSH=OK
REPORT=SyS/Temp/Handoff/MB-EXAMPLE.REPORT.txt
NEXT_ACTION=MB-NEXT
********************** AI_TAIL_END ************************

## 12. Example FAIL

********************** AI_TAIL_START **********************
AI_TAIL_SCHEMA=v1
MB_ID=MB-EXAMPLE
FINAL_STATUS=FAIL
BLOCKER=WORKTREE_NOT_CLEAN
BRANCH=lab/example
HEAD=abc1234 commit_message
DIRTY=true
FILES_CHANGED=3
FILES=path/a.txt|path/b.txt|path/c.txt
COMMIT=NONE
PUSH=NO
REPORT=SyS/Temp/Handoff/MB-EXAMPLE.REPORT.txt
NEXT_ACTION=CLEAN_WORKTREE_BEFORE_RETRY
********************** AI_TAIL_END ************************

## 13. Governance Consequence

A script without an AI_TAIL block may still be technically valid, but it is not optimal for human-AI continuity.

For long-running or verbose workflows, missing AI_TAIL should be treated as a workflow quality defect.

TITLE=Control extension: PowerShell AI Tail and execution observability
STATUS=ACTIVE
CONTROL_OBJECTIVE:
- Ensure that PowerShell automation used by AI/human repository workflows is observable, auditable, and safe.

CONTROL_REQUIREMENTS:
1. Long-running PowerShell scripts must use Write-Progress so the human sees execution progress.
2. Scripts writing to SyS\Temp must clean SyS\Temp before producing outputs and must preserve the executing script when located inside SyS\Temp.
3. Repository-mutating scripts must check git status --short before mutation and hard-stop on unexpected dirty state.
4. Scripts must not stage, commit, push, delete, rename, or normalize broad paths without explicit allowlist and forbidden-path checks.
5. Mutating scripts must run Validate-System.ps1 after mutation when available.
6. PowerShell syntax validation is mandatory through Test-PowerShellSyntax.ps1 as part of Validate-System.ps1.
7. AI tail output must use the standard AI_TAIL_START / AI_TAIL_END block with the mandatory fields.
8. The AI tail must be preceded by exactly five blank lines.
9. The script must state CANON_MODIFIED and COMMIT_PUSH_PERFORMED explicitly.
10. Any failure must end in FINAL_STATUS=FAIL and include ERROR.

EVIDENCE:
- Terminal AI_TAIL block.
- Summary file in SyS\Temp.
- Modified files list when applicable.
- Validate-System output.
- Git status and log after human commit when applicable.

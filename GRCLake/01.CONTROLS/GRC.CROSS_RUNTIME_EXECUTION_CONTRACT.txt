# GRC.CROSS_RUNTIME_EXECUTION_CONTRACT

MARKER: MB-SM-052A_CROSS_RUNTIME_EXECUTION_CONTRACT
VERSION: v1.1
STATUS: ACTIVE
LAYER: GRC
CONTROL_TYPE: EXECUTION_GOVERNANCE
PURPOSE: Enforce the human-controlled script execution method across all runtimes, not only PowerShell.

==========
00.00 CONTROL STATEMENT
==========

Any AI agent delivering an executable artifact must comply with the cross-runtime execution contract.

This applies to:
- PowerShell
- Python
- Bash
- Node
- SQL wrappers
- Docker wrappers
- Excel/VBA helpers
- Power Query generators
- any other executable/scripted runtime

==========
01.00 MANDATORY USER FLOW
==========

The canonical flow is:

A. AI gives the executable file or file content.
B. Human saves/downloads it into the project TEMP path.
C. Human runs the exact command from VS Code/terminal from any location.
D. Human returns AI_TAIL_START through AI_TAIL_END and/or explicit TEMP outputs requested by the AI.

The AI must design scripts around this flow.

==========
02.00 EXECUTION_CONTRACT_GATE
==========

Before executable delivery, the AI must satisfy:

- PROJECT
- PROJECT_ROOT
- TEMP_PATH
- SCRIPT_NAME
- SCRIPT_RUNTIME
- TARGET_SHELL
- MIN_VERSION
- CAN_RUN_FROM_ANY_LOCATION
- AI_TAIL_SUPPORTED
- EXIT_CODE_SUPPORTED
- FILE_OUTPUT_SUPPORTED
- GIT_AWARE
- AUTO_COMMIT_ALLOWED
- USER_EXECUTES_LOCALLY
- LIMITATION
- RECOMMENDATION
- DECISION

Allowed decisions:
- PROCEED: full contract can be implemented.
- ADAPT: wrapper/adapter required.
- BLOCK: unsafe or insufficient context.

==========
03.00 HARD FAIL CONDITIONS
==========

The response or script is non-compliant if it:

- delivers executable code without AI_TAIL when the runtime supports AI_TAIL;
- omits TEMP path;
- cannot run from any location;
- auto-commits or pushes without explicit authorization;
- uses git add . or git add -A by default;
- hides or ignores dirty worktree state;
- reports PASS while validation failed;
- continues after UNKNOWN_WORKTREE_STATE;
- asks the user to upload broad logs when a narrow AI_TAIL or TEMP output is enough;
- edits generated outputs directly when source/rebuild flow is required;
- treats PowerShell-specific rules as sufficient for other runtimes without an adapter.

==========
04.00 TOOL CAPABILITY DECLARATION
==========

If a runtime cannot support the full method, the AI must say so.

Required format:

TOOL_CAPABILITY:
- TOOL:
- CAN_USE_METHOD_FULLY:
- CAN_USE_METHOD_PARTIALLY:
- MISSING:
- SAFE_ADAPTER:
- RECOMMENDATION:

Examples:
Power Query M:
- CAN_USE_METHOD_FULLY: NO
- MISSING: stdout, exit code, AI_TAIL
- SAFE_ADAPTER: Python or PowerShell generator/validator
- RECOMMENDATION: generate .m files via wrapper and validate externally.

Python:
- CAN_USE_METHOD_FULLY: YES
- REQUIREMENTS: pathlib, try/except/finally, print_ai_tail, explicit exit code
- RECOMMENDATION: proceed.

==========
05.00 AI_TAIL MINIMUM CONTRACT
==========

AI_TAIL must be machine-readable and concise.

Minimum fields:
AI_TAIL_SCHEMA=v1
MB_ID=<id>
RUNTIME=<runtime>
ROOT=<project root>
TEMP_PATH=<temp path>
FINAL_STATUS=<PASS|FAIL|PASS_WITH_WARNINGS|COMMIT_READY>
BLOCKER=<NONE|specific blocker>
FILES_CREATED=<count or list>
FILES_MODIFIED=<count or list>
VALIDATION_STATUS=<PASS|FAIL|NOT_RUN>
COMMIT_PUSH_PERFORMED=NO
NEXT_ACTION=<single next action>

Additional fields are allowed when useful.

==========
06.00 GENERATED OUTPUT RULE
==========

If the target artifact is generated output, the AI must not patch it manually unless explicitly instructed.

Required sequence:
- patch canonical source;
- run generator/build;
- validate;
- report generated outputs in AI_TAIL or summary.

==========
07.00 TOKEN AND DELIVERY ECONOMY
==========

To reduce token use:
- prefer one executable script over large inline patches;
- prefer downloadable/single file when available;
- prefer AI_TAIL over long terminal logs;
- request only relevant TEMP files;
- avoid ZIP unless multi-file delivery is materially simpler or cheaper.

==========
08.00 AGENT-SPECIFIC APPLICATION
==========

For Claude, Codex, ChatGPT or other agents:
- receiving Skills/GRC context is not enough;
- the agent must explicitly pass EXECUTION_CONTRACT_GATE;
- the agent must choose the correct runtime adapter;
- the agent must stop and recommend an adapter if full compliance is impossible.

==========
09.00 REVIEW GATE
==========

A project using this GRC should periodically run a compliance audit over:
- .ps1
- .py
- .sh
- .js
- build scripts
- validators
- generated-helper scripts

Audit checks:
- AI_TAIL present;
- tail emitted on failure path;
- no hidden auto-commit;
- root/temp explicit;
- validation gate present when applicable;
- dirty state hard stop when Git-aware;
- generated output not manually patched.

SOURCE_EVIDENCE...: CloseReport runner failures and recovery flows, MB-SM-054A
PURPOSE...........:
Prevent false PASS, lost terminal evidence, ambiguous output counts and unrecoverable local runs.

AI_TAIL_STRICT_CONTRACT:
Every lifecycle runner or executable package must:
- print AI_TAIL_START / AI_TAIL_END to console;
- persist the same AI_TAIL to a file under the project Temp path;
- include AI_TAIL_SCHEMA;
- include MB_ID;
- include FINAL_STATUS;
- include BLOCKER when status is not PASS;
- include PROJECT_ROOT;
- include TEMP_PATH;
- include OUTPUT_COUNT or separate UPLOAD_OUTPUT_COUNT and TOTAL_OUTPUT_COUNT when appropriate;
- include CANON_MODIFIED;
- include USECASE_OUTPUTS_MODIFIED when relevant;
- include COMMIT_PUSH_PERFORMED;
- include CODEX_CLAUDE_EXECUTED when relevant;
- include NEXT_ACTION.

OUTPUT_COUNT_RULE:
If AI_TAIL includes AI_TAIL itself in totals, the runner must distinguish:
- UPLOAD_OUTPUT_COUNT
- TOTAL_OUTPUT_COUNT_INCLUDING_AITAIL

CHILD_PROCESS_FAIL_PROPAGATION:
If a required child process, validator, build, RADAR, Python analyzer, git command, or readiness gate fails:
- the parent runner must fail;
- FINAL_STATUS must not be PASS;
- BLOCKER must include the failing command or minimum actionable error;
- output packages generated after the failure must be marked partial or invalid.

FALSE_PASS_PROHIBITION:
A runner that logs parse/runtime failure in a required subprocess and still reports PASS fails this GRC.

DONE_WHEN:
The human can recover state from AI_TAIL alone and no required subprocess failure is hidden behind PASS.

10.00 RUNTIME AND AGENT IDENTITY DECLARATION
Every execution report must declare BOTH:
- RUNTIME: the actual interpreter/shell that executed (pwsh 7.x, Windows
  PowerShell 5.1, python 3.x, bash/WSL2, node, etc.);
- AGENT: the actual agent or human operator that drove execution (Claude Code,
  Codex, ChatGPT-guided human paste, direct human, scheduled job).
Identity is factual, not aspirational: report what actually ran.

10.10 EXECUTABLE IDENTITY EVIDENCE
Where feasible, reports should include the executable's identity evidence:
absolute path, version string, and content hash (SHA256) of the script that
ran. For repository scripts, the repo-relative path plus HEAD commit is
acceptable evidence.

10.20 TOOL OUTPUT VS PROJECT OUTPUT
Reports must distinguish:
- TOOL OUTPUT: diagnostics, logs, AI_TAIL, temp evidence produced by the
  execution tooling;
- PROJECT OUTPUT: canonical or generated artifacts of the project itself.
Tool output must never be presented as project deliverable, and vice versa.

10.30 REJECT SIMULATED OR MISLABELED EXECUTION IDENTITY
A report that claims an agent, runtime, or machine executed work that it did
not execute is non-compliant, regardless of whether the results are correct.
Simulated runs must be labeled SIMULATED. Mislabeling execution identity is a
hard failure of this GRC (see also GRC.PROJECT_CONTEXT_IDENTITY).

10.40 SHELL/RUNTIME COMPATIBILITY VERIFICATION
Before delivering an executable, verify the target shell/runtime is actually
available and version-compatible in the operator environment (e.g. pwsh vs
powershell, python launcher, WSL2 presence). Do not assume the authoring
environment matches the execution environment.

10.50 NO EXECUTION CLAIM WITHOUT EVIDENCE
Never claim that another agent (Codex, Claude, remote job) executed work
without direct evidence of that execution (its AI_TAIL, its log, its commit,
its report). Absence of evidence means the claim must not be made.

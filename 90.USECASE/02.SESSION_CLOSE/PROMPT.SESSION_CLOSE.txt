PROYECTO: Session Close

OBJETIVO:
Cerrar sesion dejando continuidad humana e IA consistente para la proxima ocasion.

INPUT:
- requerimiento del usuario
- estado actual
- BATON vigente
- WhoAmI vigente
- HUMAN si aplica
- RADAR before/after
- SKILL.MENU
- lifecycle y artifacts policy

DEBES:
1. revisar el estado actual
2. actualizar BATON
3. actualizar WhoAmI si cambio el estado humano operacional
4. actualizar HUMAN solo si cambio el entendimiento profundo
5. validar coherencia con RADAR
6. identificar si algo aprendido amerita actualizar o crear skills

OUTPUT:
- BATON actualizado
- WhoAmI actualizado si aplica
- observacion sobre HUMAN
- siguiente accion exacta
- bloque estructurado SKILL_GRC_LEARNING_REVIEW


==========
MB-GRC-015_SESSION_CLOSE_HARDENING
==========

Antes de declarar una sesion cerrada, ejecutar obligatoriamente:

powershell -ExecutionPolicy Bypass -File ".\SyS\A_Tools\SessionClose\Test-SessionCloseReadiness.ps1"

El cierre debe reportar, como minimo:

- Rama Git actual.
- Ultimo commit.
- Tags en HEAD.
- Estado Git corto.
- Diff stat.
- Diff staged.
- Archivos untracked.
- Resultado de Validate-System.ps1.
- Existencia y metadata basica de RADAR manifest.
- Existencia de los seis outputs ACTIVE de RADAR v1.4.
- Existencia y modified_at de BATON.
- Existencia y modified_at de WHOAMI.
- Ruta del reporte TXT y JSON generado.

Regla:
- OK permite cierre limpio.
- WARN exige revision humana.
- FAIL bloquea cierre limpio.


==========
MB-GRC-016_FRESHNESS_POLICY
==========

Ademas del cierre MB-GRC-015, revisar frescura de continuidad:

- HEAD_COMMIT_DATE.
- RADAR_FRESH_AGAINST_HEAD.
- BATON_FRESH_AGAINST_HEAD.
- WHOAMI_FRESH_AGAINST_HEAD.

Regla:
- Si cualquiera esta en False, reportar WARN.
- No declarar cierre limpio sin informar la deuda de continuidad.

==========

==========
MB-GRC-016C_FRESHNESS_SEMANTICS
==========

Para evaluar frescura:
- BATON/WHOAMI usan ultimo commit Git del archivo.
- RADAR usa generated_at del manifest.
- No usar LastWriteTime como criterio principal para BATON/WHOAMI.

==========
SESSION_LEARNING_REVIEW
==========

Al cierre de sesion, revisar el chat activo y outputs relevantes para detectar oportunidades de:
- crear GRC;
- mejorar GRC;
- mejorar Skills;
- registrar candidatos en backlog;
- identificar conflictos, omisiones, duplicidad o deuda tecnica;
- proponer siguiente minibattle.

Regla dura:
No crear ni modificar canon automaticamente. Toda oportunidad se registra como candidato o se ejecuta solo si el humano lo instruye explicitamente.

Bloque obligatorio de salida:

SKILL_GRC_LEARNING_REVIEW:
- NEW_GRC_CANDIDATES:
- GRC_IMPROVEMENT_CANDIDATES:
- SKILL_IMPROVEMENT_CANDIDATES:
- OPERATIONAL_RULES_TO_CANONIZE:
- DO_NOT_CANONIZE:
- CANDIDATES_REGISTER_UPDATED:
- NEXT_GRC_OR_SKILL_ACTION:

Reglas del bloque:
- Si una categoria no aplica, declarar NONE con motivo breve.
- CANDIDATES_REGISTER_UPDATED debe declarar YES o NO.
- NEXT_GRC_OR_SKILL_ACTION debe recomendar una sola accion.
- No canonizar automaticamente; registrar, proponer o escalar al humano.

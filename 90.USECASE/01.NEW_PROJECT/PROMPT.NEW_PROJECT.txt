PROYECTO: New Project Bootstrap

OBJETIVO:
Crear el set mínimo correcto para iniciar un proyecto nuevo de cualquier índole.

INPUT:
- requerimiento del usuario
- SKILL.MENU
- skills adjuntos
- policies de bootstrap, lifecycle, artifacts, WhoAmI
- standards base de BATON, HUMAN y RADAR

DEBES:
1. evaluar si el set adjunto es suficiente
2. pedir skills adicionales si faltan
3. crear propuesta para:
   - WhoAmI
   - BATON
   - HUMAN
4. definir siguiente acción
5. mantener consistencia con policies y standards

OUTPUT:
- evaluación de suficiencia del set
- skills faltantes
- propuesta de artefactos iniciales
- siguiente acción recomendada

==========
MB-GRC-027C_PROMPT_ENGINEERING_DISCOVERY_CHALLENGE
==========

REGLA:
Cuando el nuevo proyecto requiera crear, auditar o perfeccionar prompts, la IA debe aplicar 30.SKILL.PROMPT_ENGINEERING_DISCOVERY_CHALLENGE.txt.

La IA debe:
- ejecutar discovery antes de generar prompts finales;
- desafiar alcance, inputs, outputs, restricciones y criterios de éxito;
- declarar PROMPT_READY antes de generar un prompt final;
- usar DRAFT_NOT_READY si falta información relevante;
- mantener la capa pedagógica subordinada a la respuesta operacional.

La IA no debe:
- generar prompts finales sobre requerimientos incompletos;
- crear canon automáticamente;
- convertir una respuesta operacional simple en una clase.

MB-GRC-031B_IT_PROJECT_DELIVERY_CONSTITUTION
==========
When creating a new IT project, apply GRCLake/AA.CONSTITUTION.

The IA must force these decisions before proposing implementation:
1. OUTPUT_TYPE: DEPLOY_DONE or DELIVERABLE_DONE.
2. FIRST_OUTPUT_CONTRACT.
3. MINIMUM_MOCKUP.
4. MUST_HAVE.
5. NO_SCOPE.
6. MAX_HOURS / MAX_SESSIONS / MAX_COST_OR_COST_POLICY / MAX_EFFORT.
7. PLAN_B_TRIGGER.
8. PLAN_B_ACTION.
9. TIMELOG format or path.

The IA must prevent portfolio sprawl and stop-loss failure:
- Do not open additional active projects without pausing/closing another.
- Do not continue iteration by habit after Plan B trigger.
- Do not perform platform/governance work before first output unless it directly unblocks DEPLOY_DONE or DELIVERABLE_DONE.

==========
MB-GRC-031M_CONSTITUTION_AI_BRIEF_SELF_CONTAINMENT
==========

When this usecase is used for an IT project, apply the AI operating brief:

GRCLake/AA.CONSTITUTION/05.CONSTITUTION.OPERATING_BRIEF.AI.txt

Minimum required sequence before implementation:

1. Define OUTPUT_TYPE: DEPLOY_DONE or DELIVERABLE_DONE.
2. Define the first deploy or first deliverable.
3. Define the minimum mockup.
4. Define minimum functionality and characteristics.
5. Define minimum work required to satisfy the first output.
6. Define investment limits: time, cost, effort, complexity and Plan B.
7. Execute only toward DEPLOY_DONE, DELIVERABLE_DONE or stop-loss.

Do not expand platform, architecture, governance, automation, tooling or future features unless the work directly unblocks the first DEPLOY_DONE or DELIVERABLE_DONE.

==========
01.00 TASK SUMMARY
==========

Build a Python CLI that reads a YAML file containing a list of tasks and outputs
a formatted text report with filtering and sorting applied.

This spec is the canonical source of truth. Agent briefs summarize it for each
agent's specific execution context. In case of conflict, this file has authority
over agent briefs.

==========
02.00 INPUT YAML SCHEMA
==========

File format: YAML
Root key: tasks (list)

Each task item has exactly these fields:
  title     : string — task name (required)
  priority  : string — one of: high | medium | low (required)
  due_date  : string — ISO 8601 date YYYY-MM-DD (required)
  status    : string — one of: open | done | blocked (required)

Example structure:
  tasks:
    - title: "Task name"
      priority: "high"
      due_date: "2026-07-01"
      status: "open"

Sample file for testing: TASKS.sample.yaml (in this folder).

==========
03.00 CLI CONTRACT
==========

Entry point: python -m src.cli  OR  python src/cli.py

REQUIRED FLAG:
  --input PATH       Path to YAML input file. Fails with exit code 1 if file not found.

OPTIONAL FLAGS:
  --filter-status STR   Filter tasks by status value (open | done | blocked).
                        If omitted: include all tasks.
  --sort-by FIELD       Sort output by field (priority | due_date).
                        Default if omitted: priority.
                        Priority sort order: high → medium → low.
                        due_date sort: ascending (earliest first).
  --output PATH         Write report to this file instead of stdout.
                        If omitted: output to stdout.

--help flag must be present and list all flags with descriptions.

==========
04.00 OUTPUT REPORT CONTRACT
==========

Format: plain text
Encoding: UTF-8

Structure:
  Line 1: header "TASK REPORT"
  Separator line (dashes or equals)
  For each task (in sorted/filtered order):
    TITLE: <title>
    PRIORITY: <priority>
    DUE: <due_date>
    STATUS: <status>
    (blank line between tasks)
  Final separator
  Summary line: "Total: N | Open: N | Done: N | Blocked: N"

The report must be deterministic: same input file + same flags → identical output.

==========
05.00 EXIT CODES
==========

EXIT CODE 0: success — report generated (or no tasks matched filter, still success)
EXIT CODE 1: input file not found — print error to stderr, exit 1
EXIT CODE 2: invalid YAML — file exists but cannot be parsed; print error to stderr, exit 2

These exit codes are exact and mandatory. Do not use other codes for these conditions.
Do not use exit code 1 for YAML errors or exit code 2 for file-not-found.

==========
06.00 REQUIRED MODULES
==========

src/
  parser.py      — read YAML file; validate structure; return task list or raise appropriate error
  scheduler.py   — filter by status; sort by field; return ordered task list
  report.py      — format task list as text report string
  cli.py         — parse CLI args; orchestrate parser → scheduler → report → output

No additional modules. Do not create utils.py, helpers.py, config.py, or any other module
unless it is one of the four listed above. Scope creep in modules is penalized.

==========

tests/
  test_parser.py      — tests for parser.py functions
  test_scheduler.py   — tests for scheduler.py functions
  test_report.py      — tests for report.py functions
  test_cli.py         — tests for cli.py (use subprocess or argparse testing)

MINIMUM: 12 tests total across the four test files.
All tests must pass: pytest must exit 0.
Tests must be runnable with: pytest tests/ (from pilot root directory).
No test may depend on external network access.

Suggested test coverage (non-exhaustive):
  test_parser.py:
    - load valid YAML → returns correct task list
    - missing file → raises FileNotFoundError (or equivalent)
    - invalid YAML content → raises appropriate error
  test_scheduler.py:

    - sort by due_date → ascending order

  test_report.py:
    - non-empty task list → report contains TITLE and STATUS
    - empty task list → report still valid (no tasks, summary shows 0s)
  test_cli.py:
    - --input with valid file → exit code 0
    - --input with missing file → exit code 1
    - --input with invalid YAML → exit code 2
    - --filter-status filters output correctly
